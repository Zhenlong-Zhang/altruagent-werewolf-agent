# Round04 plan: strategy capability before further tuning

Planner recommendation, 2026-11-20. Architecture review only; implementation starts after parent synthesis and Reviewer acceptance. Preserve D7 IDs/greedy/no-guard as the release/control. R03 F/G are now development evidence; they cannot be Round04's final test.

## Diagnosis from the actual implementation

The principal constraint is not simply insufficient network size. `hybrid.py` ranks offered IDs rather than generating new speeches. Its speech choices share a few fixed targets/templates; `choose_message` terminates after one attempt per day, before a response to newly received evidence. `_view` retains only the last10 message envelopes and240 characters per message for the model; filtering after slicing can discard more useful public context. Important old claims can disappear even though `_messages` retained them. The semantic actor embeds candidate labels plus eight coarse state fields, not the actual claims, investigations or deduction. Therefore different social states can yield the same learned representation.

R03 trained on30 independent terminal outcomes/136 sampled choices. Its old critic was identically zero when fixed advantages were computed; fitting a critic afterwards did not feed learned value estimates into that update. This was valid terminal-return PPO, not a demonstrated variance-reduced, multibatch actor–critic learner. The trained greedy policy changed1/98 observed eligible G choices. More epochs on those data cannot create missing tactics or evidence. One direct LLM plus five rules opponents also exposes little of the deception and negotiation expected against competitors.

Worker's independent audit also found correctness gaps to fix before interpreting new training: repeated untrusted accusations can overcome the current confirmed-nonwolf suspicion penalty before its final clamp, and speech heuristics can invert a verified fact. Preserve verified facts as immutable constraints, separately from accumulated suspicion/claims; test arbitrarily repeated accusations rather than relying on a large negative score. At discussion-to-vote transition, the termination payload may contain final messages that the runner currently ignores, while the next vote state's `new_messages` is empty. Refresh the acting seat's authorized `get_messages` into an isolated SDK snapshot before building the vote state, with sequence deduplication. Do not mutate a shared official SDK or fetch another seat's view.

## Recommended route and sequence

1. **Reuse real released capability, screen before training.** Compare the current vanilla Qwen3-8B with the author-released [MARSHAL-Generalist-Qwen3-8B](https://huggingface.co/nics-efc/MARSHAL-Generalist-Qwen3-8B), pinned `369d9decea6e8b347f81706fa169dbbddddce360`. Its strategic RL training is real but involves other games, so Werewolf transfer is an experiment. Use the identical new observation/candidate interface, actual GPU allocation and decoding budget for both. Measure factual fidelity, target/seat equivariance, diverse useful candidates, valid delivery, peak VRAM and latency. Check deliberate wolf deception separately from accidentally corrupting private knowledge. Add a14B challenger only if measured8B behavior or latency makes that comparison useful; GPU eligibility is not a memory/throughput guarantee.

2. **Make state and language actions meaningful.** Maintain a seat-isolated, append-only evidence record: own private facts, public engine facts, attributed player claims with message IDs, contradictions, own public commitments, votes and deaths. Never upgrade an assertion to a verified fact. Give the proposer a bounded recent transcript plus persistent per-player claim/evidence summaries; deterministic facts and provenance must survive truncation. Expose the complete current legal action set rather than a model-truncated top-ranked slate for nonlanguage decisions. Generate three distinct contextual speech candidates by explicit intents, with Pass and a legal canonical fallback: disclose/withhold information, ask a concrete question, challenge a contradiction, defend, consolidate a vote; wolves additionally may select a deliberate bluff/cover story. Store intended tactic, recipient, evidence references, target and surface text separately. Fact consistency and permitted deception are different checks.

   **Accepted Phase A realization amendment:** the three candidates are structured model-generated plans, not unrestricted generated prose. Their typed assertions, intent, targets and audience are realized by canonical renderers (`typed-canonical-v1`), and model-supplied text must be empty. This still expands contextual evidence disclosure, attributed challenge, defense, vote commitment, explicit wolf bluff and private coordination beyond R03. It does not reproduce SLA's free-form language action space. A later free-form realization ablation needs separate acceptance; regex checks cannot prove arbitrary prose factual or private-safe.

3. **Allow responsive communication without unlimited chatter.** Replace the one-message/day latch with acknowledged-message accounting and a finite opening/response/commitment controller. Initially allow at most three accepted messages per window including any private wolf-buddy message, within the platform's five-message,50-word,1024-character and120-second limits. Send at most one response to genuinely new relevant evidence, prevent repeated equivalent claims, and refresh visible messages before the vote. Private coordination addresses only a living confirmed wolf teammate. Adapt SDK behavior and quota/timeout/retry handling with tests before live rollout. This remains an experimental controller, not an assertion that more speech wins.

4. **Train a contextual strategy policy from new trajectories.** Prefer adapting the real MIT [SLA](https://github.com/zelaix/SLA)/[MAPPO](https://github.com/marlbenchmark/on-policy) rollout, masking, return and value-learning components over another isolated one-batch optimizer. Use a local frozen encoder over structured evidence/player summaries and candidate text, plus exact numeric role/legal/time features. Keep facts in separate slots rather than truncating one giant sentence to256 wordpieces. Train on successive fresh on-policy batches, with values from the previous frozen collection policy informing the next batch's advantages. Explicitly handle death, terminal masks, asynchronous turn intervals, tactic availability and message delivery. An actor observes only its seat's permitted information. Begin with a decentralized critic; call this PPO unless a separately reviewed joint/centralized training protocol actually implements MAPPO. The revised writer must record complete before-action context, values, logits, action/tactic/text, ACK and terminal transitions. Old coarse logs cannot reconstruct this missing training state.

5. **Use a population and distinguish architecture from learning.** Freeze a training population containing D7, direct vanilla LLM, released strategic LLM and the new untrained candidate policy, with declared sampling weights. Include LLM teammates and opponents, not five rules agents in every game. Different stochastic styles from one model do not establish independent model generalization. Reserve a different opponent-mixture/seed namespace for final evaluation. Compare incumbent; new interface without learned adaptation; the same interface after adaptation. This separates a stronger proposer/controller from RL improvement. Optionally log all training seats, but treat games as correlated clusters and keep every seat's private context isolated.

6. **Freeze measured budgets and then evaluate once.** After a short operation-only GPU throughput measurement, parent sets a finite rollout/update budget, batch count and evaluation sample size before training-outcome inspection. Aim beyond the previous30 terminal observations through multiple fresh batches; do not prescribe10M steps merely because a paper used them. Freeze checkpoint-selection rules using development games, then freeze the selected artifact for a fresh final cohort. Report wins by role/seat and opponent mixture, game-level uncertainty, legal/ACK/fallback rates and latency tails. Keep D7 if improvement is unestablished. Package release plus fallback, full provenance, training logs and unchanged competition entry assumptions.

## Reuse decision

Use MARSHAL weights as a zero-shot contender; use MIT SLA/MAPPO code as attributed engineering references/components; adapt the ONUW tactic-selection idea without assuming its checkpoint transfers. Do not begin a full LSPO/CFR/DPO reproduction or MaKTO-scale token training before the new interface and model screen. Those require substantially more appropriate data and, for CFR, a validated counterfactual environment. A later token-level LoRA experiment may use the MIT MaKTO dataset after rules/private-information filtering, but remains a separately evaluated generator change. See [literature fit](07_literature_fit.md) for verified sources, licenses and limits.

Implementation then gets its own exact contract and tests.
