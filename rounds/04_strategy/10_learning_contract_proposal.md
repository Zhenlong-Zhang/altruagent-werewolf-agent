# Phase C contextual learning and population contract proposal

Planner proposal, 2026-11-20. No implementation or new training authorized by this document alone. Phase A source/model screen is frozen at `75a6cd6`, job2184358; do not change that experiment. Parent/Reviewer accept exact Phase B transport/controller first, then append measured compute and game budgets before Phase C collection. Winning strength remains open after the model screen.

## 1. Capacity and observable state

Use the accepted `strategy-observation-v1`/`strategy-candidates-v1` packet, including typed canonical realization. Proposed initial network: width128, two attention blocks/four heads, dropout0; frozen pinned MiniLM384 encodes **each slot separately**, never one giant concatenated history. Actor receives only its own authorized packet. Projection plus slot-type, numeric truth/role/legal/time fields and explicit subject/target pointers provides:

- One global token: own role, day/phase, live/dead mask, available quota/time and completeness diagnostics. No winner/terminal reward/evaluation-only roles.
- Seven persistent player tokens: alive flag, own-known alignment/source, public votes, own ACKed commitments and bounded attributed claim summary. Unknown is a distinct value, not nonwolf.
- Protected verified-fact tokens, deduplicated by source/subject/predicate, including negative checks as **nonwolf**, never falsely asserting villager. Reserve capacity32; overflow is explicit unsupported-state/fallback, never silent fact truncation. Metadata binds source, subject and first-known sequence.
- Up to four attributed-claim tokens per player: two most recent, one unresolved contradiction and one older relevant claim, deduplicated by source sequence. Freeze deterministic retention/tie-breaking in the serializer. Full raw ledgers stay archived; these are bounded summaries, not complete-history equivalence. Private envelopes require the current owner/recipient authorization.
- Current candidate tokens: all current engine-legal nonlanguage actions, or the validated typed speech plans plus Pass/fallback. Include intent, recipient/channel, exact target pointers, evidence-reference alignment, canonical realization embedding and model/rule signals. Candidate padding is not an actual action.

Keep numeric protected facts separate from text embeddings: no learned similarity may rewrite their meaning. Candidate scoring cross-attends to state/player/claim tokens, with a shared per-candidate scalar head. Mask padding and transport-invalid speech only; verified innocence is a feature/prior rather than removal of an engine-legal vote. No absolute candidate-position embedding. Typed target/seat permutations must permute corresponding scores; arbitrary natural-language aliases require explicit normalization and adversarial tests rather than an unsupported exact-equivariance claim. Test two otherwise identical packets whose evidence differs: the network input and potentially the preferences must differ. MiniLM pooling/truncation applies per bounded slot; report slot overflow/retention counts.

Use a separately parameterized decentralized critic over the same seat-visible state (and observed candidate availability), with its own attention/value parameters. Only frozen encoder weights may be shared initially. Critic updates cannot silently change actor logits. No other-seat private observations, joint action decoder or central ground-truth role vector enter either model. Algorithm label: **contextual PPO**, not full MAPPO.

## 3. Warm start and learning controls

Keep the Phase A-selected generator, typed realizer and Phase B controller frozen for a training lineage. If random slate selection is clearly unsuitable, collect a separate new-generator demonstration set: full packets/slates plus the **actual recorded teacher/controller choice**, not an assumption that the first generated candidate is best. Behavior clone those choices across roles on game-disjoint train/development splits; fit the decentralized value model to completed terminal returns on training games only. Do not label all winner actions good or all loser actions bad.

Freeze this BC checkpoint as `C0`. Collect fresh sampled on-policy batches from `C0`, update to `C1`, then collect the next batch from that frozen updated actor/critic. Later collectors use learned previous-critic values rather than resetting to zero. No replay of old R03 coarse contexts or BC/off-policy logs as PPO data. A control retains `C0` without PPO while the adapted arm uses the selected later checkpoint; identical generator/controller/decoder/opponent configuration isolates RL improvement. D7 remains the whole-system incumbent comparison. BC is learning too: describe `C0` as pre-PPO, not untrained. A direct new-LLM chooser can be a development diagnostic, not a substitute for this matched learning control.

## 4. Event-time credit and delivery semantics

An actor timestep is one policy decision/request, not an SDK poll, generated token or wall-clock second. Propose gamma1 to match eventual faction wins without rewarding shorter games; GAE lambda0.95 is a proposed bias/variance setting to freeze before collection, not a paper-faithfulness claim. For each stored behavior prediction `V_old(t)`, compute once:

`delta_t = r_t + gamma * bootstrap_t * V_old(t+1) - V_old(t)`

`A_t = delta_t + gamma * lambda * trace_t * A_(t+1)`; value target `A_t + V_old(t)`. At a clean fragment boundary use bootstrap1/trace0; at true terminal both are0. Lambda0.95 creates event-count-dependent estimator bias: extra speech requests alter GAE propagation even with gamma1, so gamma1 alone does not eliminate that sensitivity.

Advantages/targets remain fixed within optimizer epochs. Terminal reward is faction score(-1/+1), zero otherwise; no unverified paper reward shaping. **Death is not faction terminal.** Remove dead seats from future actionable decisions, but link their final alive decision through to the eventual faction outcome; do not zero its return because an `active_mask` became0. The final such link has no bootstrap. Idle intervals do not add arbitrary reward/discount steps. Forced singleton actions may inform values but have zero categorical actor gradient. Terminal win before any actionable decision provides game/evaluation evidence, not an invented actor sample.

Record requested candidate, draw index/full probabilities/logp, typed payload, transport attempts, exact ACK, executed effect and postrequest state separately. Recommended MDP action is the sampled **request** through a fixed executor: rejected sampled requests remain observed request outcomes, not silently discarded draws, and any deterministic fallback is a separately marked executor effect with no fabricated sampling probability. Own public claims enter memory only on ACK/reconciled transcript. Unknown delivery is unresolved until reconciliation; never relabel a request as an acknowledged fallback or use a future receipt as if known before selection. If the implementation instead trains acknowledged executed actions only, it must justify the transformed behavior distribution; dropping rejection-dependent samples is not automatically on-policy.

Prefer complete trajectories to known faction outcome for this first learner. At a clean technical batch boundary with authorized next state and `V_old(next)` available, bootstrap and stop GAE recursion across the fragment; this is not a loss. Unknown delivery is an observed executor condition, not inherently an ineligibility reason when request/log-probability, known terminal faction outcome and subsequent authorized observations are intact. Missing ownership/propensity/state or unresolved terminal provenance is different: archive such episodes, freeze eligibility rules before collection and report their action/role-dependent censoring. Never score scheduler expiry or disconnect as a faction loss. Emit independent fields for bootstrap, trace, actor eligibility, value eligibility, reset and truncation; one overloaded `done` flag is insufficient. Actor observations must include pending status, attempt counts and remaining quota as well as accepted commitments.

## 5. Optimizer and validity requirements

Use the reused clipped PPO/value objective with explicit role/game reduction, entropy, learning rates, epoch limits and minibatch sizes frozen in the later implementation contract. Minibatches may contain multiple seats, but uncertainty/sample accounting remains by game. Store frozen full-slate probabilities/values and reproduce them before an update; check candidate/encoder/controller/source identities. Use exact full-categorical KL on the collected slates, gradient clipping and full actor/critic/optimizer rollback on nonfinite or rejected trust-bound updates. Avoid critic-only changes to an accepted actor through parameter sharing. Initial settings can follow the accepted core's conservative defaults; they must not be selected using final-cohort wins.

Required fixtures: old learned values change next-batch advantages; same advantages remain fixed across epochs; death-before-team-win retains positive return; true loss/death differs from technical truncation; rejected request versus deterministic fallback retains correct probabilities; singleton/padding/dead steps cannot contribute actor gradients; two owners cannot share hidden state; all known facts survive truncation; padded slots cannot affect logits; actor/value parameter isolation and rollback work. Also verify the population rollout schema on an actual completed game before scaling.

## 6. Population, compute and evidence budget

Use a versioned frozen pool with genuinely distinct policies/weights: D7, vanilla8B direct, MARSHAL8B direct, and a frozen new-context strategy policy, with declared mixture weights and seat assignment before each batch. The focal learner must sometimes have LLM teammates as well as LLM opponents. Hold the population stationary within a collected batch; any update of population members creates a new version. Two prompt styles on one model are policy diversity, not independently trained model diversity.

Share one stateless inference service per loaded checkpoint across seat-isolated clients; never automatically load an8B copy per seat. Models may occupy separate GPUs only if measured memory permits. Every request carries the full authorized prompt and absolute deadline; no shared conversational history or cross-seat KV cache. Bound concurrency, queue TTL and stale-request cancellation. Measure realistic synchronized discussion bursts, including generation and queue latency, before choosing how many LLM seats or concurrent games fit the120-second window. If four LLM seats cannot meet tails, reduce concurrent requests or choose a validated faster decoding budget; do not assume GPU eligibility implies viable7-seat throughput.

After Phase A/B operation-only measurements, parent freezes a finite compute envelope, number of fresh batches/games per batch, BC budget if any, checkpoint-selection rule, final evaluation counts/creation caps and time reserve. No arbitrary counts are imposed now. The design must provide more than one fresh batch so a learned critic is actually used during subsequent collection; effective sample size is completed games, not slots/decisions/epochs. Record role/seat/population exposure and all created failures. Finish with a new namespace/seed and withheld opponent mixture comparing D7, `C0` and adapted `Ck`, including deployment sampling modes decided before final outcomes. Report uncertainty and operational tails; do not promote on training loss or model-screen success alone.
